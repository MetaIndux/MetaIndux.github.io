# 成员科研介绍填写与提交

成员直接在 GitHub 仓库中编辑本人资料。请先从下方选择对应身份的独立完整模板，不需要填写网站表单。

## 按身份选择完整模板

| 本人身份 | 完整模板 |
| --- | --- |
| 在读博士 | [phd.md](phd.md) |
| 在读硕士 | [master.md](master.md) |
| 已毕业博士 | [phd-alumni.md](phd-alumni.md) |
| 已毕业硕士 | [master-alumni.md](master-alumni.md) |
| 博士后 | [postdoc.md](postdoc.md) |
| 助理研究员 | [assistant-researcher.md](assistant-researcher.md) |
| 研究员 | [researcher.md](researcher.md) |
| 助理教授 | [assistant-professor.md](assistant-professor.md) |
| 教授 | [professor.md](professor.md) |

每份文件包含标题、简短复制说明和一个完整 Markdown 代码块。**只复制代码块内部从第一行 `---` 到最后 `</div>` 的全部内容**，不复制外部标题、说明或代码围栏，不拼接多份模板。

仓库中的文件、照片、提交记录及 Pull Request 都是公开的，请只填写可以公开展示的资料。模板不对应真实人物，姓名、年份、年级等占位内容必须替换为本人资料；与所选身份对应的固定配置值保留。

## 更新已有成员

1. 打开 [`_members` 成员目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/_members)，找到本人的 `<slug>.md` 文件。`slug` 是文件名，例如姓名的英文拼写；不要为已有成员重复创建文件。
2. 打开文件并点击编辑按钮。保留最上方两条 `---` 之间的 YAML 配置及其格式，按下文说明更新资料，在配置下方按对应身份模板填写正文。
3. 保留原文件名、已有 `slug`（如有）、`name`、`role` 和 `group` 的值；毕业时设置 `status: "alumni"`，不要通过改名或随意换组来移动成员。文字值按下文规范使用英文半角双引号。
4. 保留已有准确的英文别名 `aliases`、照片和学术链接。已有详细介绍应按需补充，尤其不要用样例覆盖 PI 的完整简介。

## 新增成员

1. 从[完整模板索引](#按身份选择完整模板)打开与本人真实身份对应的独立文件。复制其中代码块内部的**全部内容**，从第一行 `---` 到最后的 `</div>`；不要复制外部标题、说明或代码围栏，不要拼接多个模板。
2. 在 [`_members` 目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/_members)使用 **Add file → Create new file**，新建 `<slug>.md`，例如以本人姓名的英文拼写组成文件名。请先确认没有重名文件，并与维护者确定稳定的文件名。
3. 粘贴所选完整模板，按文件中的注释填写姓名、英文署名、培养信息、照片、联系方式和正文。模板已固定对应身份的 `role`、`group`、`status` 和适用的 `degree`，无需自行选择代码值；若模板身份不符，应重新选择正确模板。新成员文件应放在 `_members/` 下，**不要放进 `_members/template/`**，也不要直接把模板文件改成个人资料。

## 必填信息与 YAML 字段

所有成员填写真实姓名、英文署名、当前身份、单位和明确的 `status`。**`role`、`group`、`status` 都是必填字段，不是选填项；对应身份的完整模板已经填好，无需在文件中自行挑选代码值。** 学生指在读博士生或硕士生；毕业成员指相应培养阶段已毕业的成员；教师、博士后等按非学生规则填写。各字段的具体格式注释位于所选完整模板内。

所有文字值统一使用英文半角双引号 `"`，包括姓名、每项英文别名、`role`、`group`、`degree`、`status`、`description`、`affiliation`、每项 `schools` 的学院名称、`study_year`、`image` 和每项 `links` 的值。**填写文字时只替换引号里面的内容，将 `【】` 和其中的提示一同删除，保留外侧双引号、字段名和冒号。** 外侧不要用中文引号代替英文半角双引号；内容里需要引号时用中文引号“”。正文中的占位提示也要删除，但普通 Markdown 正文不需要套引号。

年份是数字例外：`enrollment_year`、`graduation_year` 填写四位阿拉伯数字整数，例如 `2023`。只替换数字，**不加引号，不加“年”或月份，不填小数**；`"2023"`、`2023年`、`2023-09`、`2023.0` 都不符合本模板规范。不得填写预计毕业年份。`study_year` 则是带双引号的中文文本，例如 `"博士三年级"`，不是整数。

| 字段 | 必填条件 | 填写方法 |
| --- | --- | --- |
| `name` | 必填 | 本人中文姓名，用双引号包住。更新已有文件时保留原姓名，姓名纠错应与维护者确认。 |
| `aliases` | 必填列表，至少一项 | 填本人英文论文署名，每项都使用双引号。`aliases:` 独占一行；下面每项先缩进 **2 个半角空格**，再写 `-`、**1 个半角空格**和带引号的署名。保留已有有效别名，不填写其他同名作者的名字。 |
| `role` | 必填，完整模板已固定 | 新增成员保留所选身份模板中的带引号角色值。更新已有成员时保留原角色值并使用双引号。 |
| `group` | 必填，完整模板已固定 | 新增成员保留所选身份模板中的带引号分组值。更新已有成员时保留原分组值并使用双引号，毕业时不改原组。 |
| `degree` | 学生与毕业成员必填，模板已固定；非学生整行删除 | 博士模板固定为 `"phd"`，硕士模板固定为 `"master"`，对应本次展示的培养阶段。研究人员完整模板不包含此字段。 |
| `status` | 必填，完整模板已固定 | 在读／在岗模板固定为 `"active"`，毕业模板固定为 `"alumni"`。必须先选对本人真实状态对应的模板；更新已有成员的毕业状态时改为 `status: "alumni"`。 |
| `enrollment_year` | 学生与毕业成员必填；非学生整行删除 | 填该博士或硕士阶段的四位阿拉伯数字入学年份，不加引号。不要用本科入学年份替代。 |
| `study_year` | 仅在读学生必填；毕业成员和非学生整行删除 | 填本人确认的当前年级，例如 `"博士三年级"` 或 `"硕士二年级"`。这是带引号的文本，由本人和维护者手动更新，不自动计算。 |
| `graduation_year` | 仅已毕业成员必填；在读学生和非学生整行删除 | 填实际毕业的四位阿拉伯数字年份，不加引号，不填预计毕业年份。 |
| `description` | 必填 | 用双引号包住已确认的中文身份说明，与当前状态一致。 |
| `affiliation` | 必填 | 用双引号包住所属单位，例如北航填写 `"Beihang University"`；已有正确单位值沿用。 |
| `schools` | 选填学院列表，未确认时保留空列表 | 默认写 `schools: []`，其中 `[]` 不加引号。填写时改为 `schools:`，下面每个学院独立一行，以 2 个半角空格、`-`、1 个半角空格和带双引号的学院名称组成；支持填写多个学院。 |
| `image` | 个人照片选填，字段保留 | 用双引号包住已上传照片路径，例如 `"/images/people/本人照片文件名.jpg"`。无个人照片时统一保留 `image: "/images/fallback.svg"`，不留空、不删除字段。 |
| `links` | 各子项选填 | 没有公开链接时保留模板的 `links: {}`，其中 `{}` 不加引号。有链接时按下面步骤启用模板中对应的注释行。 |

`aliases` 的格式如下；填写时替换引号内的全部提示，至少保留一项：

```yaml
aliases:
  - "【本人英文论文署名】"
```

`affiliation` 填学校或机构，`schools` 填本人确认的所属学院，两者不能混用。学院名称不根据姓名、研究方向或同组成员推断；各模板默认保持空列表，待本人填写。

- **尚未确认或暂不填写学院**：保留 `schools: []`，`[]` 不加引号；删除下方带占位提示的学院注释行，不留空名称。
- **填写一个学院**：把 `schools: []` 改为 `schools:`，仅删除第一条学院示例行开头的 `#`，保留其后 **2 个半角空格**。将双引号内的提示替换为实际学院名称，删除第二条学院注释行。
- **填写多个学院**：同样改为 `schools:`，取消需要的学院示例行的注释，每个学院单独一行；每行均缩进 **2 个半角空格**，再写 `-`、**1 个半角空格**和带双引号的学院名称。超过两项时按相同格式复制列表行，不将多个学院用逗号合并成一个字符串。不需要的学院注释行整行删除。

完整模板均使用 `links: {}`，下方以 `#  email: "..."` 等注释行列出可填写的子项。没有公开链接时保留 `links: {}`，并删除下方带 `【】` 的全部注释子项行。有公开链接时，按顺序操作：

1. 将原来的 `links: {}` 改为 `links:`；文件中只保留**一个 `links` 键**，不要另起第二个。
2. 仅删除需要使用的子项行首的 `#`，保留其后的 **2 个半角空格**，使子项缩进在 `links:` 下方；不要使用 Tab。
3. 按该完整模板中的格式注释，只替换子项双引号内的提示，填写本人真实值。邮箱、主页和各学术账号的值都使用英文半角双引号。
4. 不需要的子项整行删除。不要保留 `email:` 或 `email: ""` 等空项；删完所有子项后恢复为 `links: {}`。

例如只提供公开邮箱时，使用以下结构并替换提示：

```yaml
links:
  email: "【本人愿意公开的学术邮箱】"
```

成员无需填写 `order`。博士生组、硕士生组及团队页最下方的毕业成员组，分别按 `enrollment_year` 从早到晚排序；同年入学按文件名排序，未填写入学年份的成员放在对应组末尾。研究人员的显示顺序由维护者管理。

不要把 `YYYY`、方括号提示或“待替换”当作真实资料提交。**不得从姓名、照片或入学年份猜测是否毕业、当前年级，也不得通过年份相减自动确定年级。** 尚未确认的资料先向本人核实；不要用假定的毕业状态替换现有记录。

毕业成员保留原 `role`、`group` 和个人页 slug，设置 `status: "alumni"` 后会集中展示在团队页最下方，原个人页面链接不变。仓库兼容已有的 `group: "alumni"`、`group: "phd-alumni"`、`group: "master-alumni"` 及 `role: "phd-alumni"`、`role: "master-alumni"`，不必为更新介绍而改写这些旧分类；也不要把已毕业成员误改为 `"active"`。

## 正文内容

- **个人简介**：建议 100–200 字，说明真实身份、主要研究问题、方法和应用场景。
- **研究方向**：建议 3–5 项，每项写“方向名称：具体研究问题”。
- **代表工作**：建议 2–5 项，可以是论文、公开项目、软件或数据集。沿用完整模板中的 `<div class="member-citations" markdown="1">` 容器，以紧凑有序列表呈现。每条工作写成一个连续的引用段落，依次包含题名、原作者顺序或真实参与者、发表或发布平台、年份和实际状态、一句话简介及本人已确认贡献、真实公开链接；仅加粗题名，不使用三级／五级标题或逐字段列表。多项工作只复制列表条目并依次编号。代码或数据链接选填，没有时删除该链接及其前面的间隔符。没有公开工作时删除整个容器和列表，在本节写“暂无”。预印本、投稿和已录用应区分，不能从作者顺序推断个人贡献。
- **公开联系方式**：本节选填，填写愿意公开的学术邮箱及相关说明。已通过 `links` 展示邮箱时可写“邮箱见个人资料栏”；不提供公开联系方式时删除本标题和整段。`links` 中的主页、Google Scholar、ORCID、GitHub 等可以沿用，不需要重复堆放全部链接。

已有 PI 长简介和其他已经核实的丰富正文可保留原有结构，不强制缩减为四节。样例中的文字只是格式提示，不能作为真实经历发布。

## 上传个人照片

在 [`images/people` 目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/images/people)使用 **Add file → Upload files** 上传本人照片；使用 Fork 时上传到自己的 Fork 中。然后把成员文件的 `image` 双引号内的内容改为已上传照片的完整仓库路径，例如 `image: "/images/people/本人照片文件名.jpg"`；PNG 文件保留实际的 `.png` 后缀。

建议使用 JPG 或 PNG、至少 600×600 像素、3 MB 以内；头像清晰、头肩完整、背景简洁，并留出方形裁剪空间。照片应可公开展示。已有有效照片且本次不更换时，保留原路径并使用双引号；没有个人照片时统一保留 `image: "/images/fallback.svg"`。不要删除 `image` 行或留空，不要把本地电脑路径或尚未上传的文件名填入 `image`。

## 提交修改

- **有仓库写入权限**：编辑完成后点击 **Commit changes**。按仓库权限设置提交到允许的分支，或创建分支后发起 Pull Request；提交说明写清更新了哪位成员及哪些内容。
- **没有仓库写入权限**：先 **Fork** 仓库，在自己的 Fork 中修改成员文件、上传照片并 Commit，然后向 `MetaIndux/MetaIndux.github.io` 的 `main` 分支发起 **Pull Request**，由维护者检查后合并。

照片路径和成员文件需要对应；使用分支或 Fork 时，将它们放在同一次修改中。不要改动其他成员资料、站点模板或发布生成文件。

提交前检查：姓名与身份准确；学生培养阶段、入学年份、年级或毕业年份已核实；所有文字值使用英文半角双引号，两个年份字段是未加引号的四位整数；条件不适用的字段已整行删除；链接有效且没有空子项；使用个人照片时照片已上传，否则保留统一占位路径；所有样例占位文字和 `【】` 已删除；公开联系方式经过本人确认。

Commit 或 Pull Request 不等于网站已经发布。变更进入 `main` 后，还需等待 GitHub Actions 构建和 GitHub Pages 部署成功，再检查正式个人页面。`_members/template/` 只存放填写说明与模板，不作为成员资料发布。
