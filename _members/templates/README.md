# 成员科研介绍填写与提交

成员直接在 GitHub 仓库中编辑本人资料。这里提供一份 [可复制的样例文件](example.md)，不需要填写网站表单。

仓库中的文件、照片、提交记录及 Pull Request 都是公开的，请只填写可以公开展示的资料。样例不对应真实人物，所有占位内容和示例选项都需要替换。

## 更新已有成员

1. 打开 [`_members` 成员目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/_members)，找到本人的 `<slug>.md` 文件。`slug` 是文件名，例如姓名的英文拼写；不要为已有成员重复创建文件。
2. 打开文件并点击编辑按钮。保留最上方两条 `---` 之间的 YAML 配置及其格式，按下文说明更新资料，在配置下方填写四节正文。
3. 保留原文件名、已有 `slug`（如有）、`name`、`role`、`group` 和 `order`；毕业时设置 `status: alumni`，不要通过改名或随意换组来移动成员。
4. 保留已有准确的英文别名 `aliases`、照片和学术链接。已有详细介绍应按需补充，尤其不要用样例覆盖 PI 的完整简介。

## 新增成员

1. 复制 [example.md](example.md) 的全部内容。
2. 在 [`_members` 目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/_members)使用 **Add file → Create new file**，新建 `<slug>.md`，例如以本人姓名的英文拼写组成文件名。请先确认没有重名文件，并与维护者确定稳定的文件名和展示顺序。
3. 粘贴样例，替换姓名、身份、英文署名、培养信息和正文，删除不适用的占位内容。新成员文件应放在 `_members/` 下，**不要放进 `_members/templates/`**，也不要直接把 `example.md` 改成个人资料。

## 必填信息与 YAML 字段

所有成员填写真实姓名、英文署名、当前身份、单位，并明确维护 `status`。学生与毕业成员还必须填写博士／硕士阶段、该阶段入学年份以及毕业状态；在读时填写当前年级，已毕业时填写实际毕业年份。教师、博士后等不适用学生培养信息的身份可删除相应学生字段。

| 字段 | 填写方法 |
| --- | --- |
| `name` | 本人中文姓名。更新已有文件时保留原值，姓名纠错应与维护者确认。 |
| `aliases` | 本人的英文论文署名；保留已有有效别名，不填写其他同名作者的名字。 |
| `role`、`group` | 新增博士生通常均填 `phd`，新增硕士生通常均填 `master`；其他身份请与维护者确认。更新已有成员时保留原值。 |
| `order` | 展示顺序，与维护者确认；更新已有成员时保留原值。 |
| `degree` | 博士阶段填 `phd`，硕士阶段填 `master`。对应本次展示的培养阶段。 |
| `status` | 在读／在岗填 `active`，已确认毕业填 `alumni`。必须依据本人真实状态明确填写，不能把样例中的选项直接当作本人状态。 |
| `enrollment_year` | 该博士或硕士阶段的入学年份，填写四位数字，不加引号。不要用本科入学年份替代。 |
| `study_year` | 在读成员填写本人确认的当前年级，如 `博士三年级` 或 `硕士二年级`；由本人和维护者手动更新，不自动计算。毕业后删除此字段。 |
| `graduation_year` | 仅已毕业成员填写实际毕业年份，四位数字，不加引号；在读时删除，不填预计毕业年份。 |
| `description` | 已确认的身份说明，与当前状态一致。 |
| `affiliation` | 所属单位；沿用已有正确值。 |
| `image` | 仓库中照片的路径，例如 `/images/people/本人照片文件名.jpg`。 |
| `links` | 愿意公开的学术邮箱和学术账号；没有相应链接时可保留 `links: {}`。 |

不要把 `YYYY`、方括号提示或“待替换”当作真实资料提交。**不得从姓名、照片或入学年份猜测是否毕业、当前年级，也不得通过年份相减自动确定年级。** 尚未确认的资料先向本人核实；不要用假定的毕业状态替换现有记录。

毕业成员保留原 `role`、`group`、`order` 和个人页 slug，设置 `status: alumni` 后会集中展示在团队页最下方，原个人页面链接不变。仓库兼容已有的 `group: alumni`、`group: phd-alumni`、`group: master-alumni` 及 `role: phd-alumni`、`role: master-alumni`，不必为更新介绍而改写这些旧分类；也不要把已毕业成员误改为 `active`。

## 正文填写四节

- **个人简介**：建议 100–200 字，说明真实身份、主要研究问题、方法和应用场景。
- **研究方向**：建议 3–5 项，每项写“方向名称：具体研究问题”。
- **代表工作**：建议 2–5 项，可以是论文、公开项目、软件或数据集。写清标题、作者、年份、状态、工作简介、本人实际贡献和链接；没有公开工作可写“暂无”。预印本、投稿和已录用应区分，不能从作者顺序推断个人贡献。
- **公开联系方式**：填写愿意公开的学术邮箱及相关说明。`links` 中的主页、Google Scholar、ORCID、GitHub 等可以沿用，不需要重复堆放全部链接。

已有 PI 长简介和其他已经核实的丰富正文可保留原有结构，不强制缩减为四节。样例中的文字只是格式提示，不能作为真实经历发布。

## 上传个人照片

在 [`images/people` 目录](https://github.com/MetaIndux/MetaIndux.github.io/tree/main/images/people)使用 **Add file → Upload files** 上传本人照片；使用 Fork 时上传到自己的 Fork 中。然后把成员文件的 `image` 改为对应的 `/images/people/文件名.jpg` 或 `.png`。

建议使用 JPG 或 PNG、至少 600×600 像素、3 MB 以内；头像清晰、头肩完整、背景简洁，并留出方形裁剪空间。照片应可公开展示。没有新照片时保留现有图片；新成员暂未提供照片可使用样例中的默认头像。不要把本地电脑路径或尚未上传的文件名填入 `image`。

## 提交修改

- **有仓库写入权限**：编辑完成后点击 **Commit changes**。按仓库权限设置提交到允许的分支，或创建分支后发起 Pull Request；提交说明写清更新了哪位成员及哪些内容。
- **没有仓库写入权限**：先 **Fork** 仓库，在自己的 Fork 中修改成员文件、上传照片并 Commit，然后向 `MetaIndux/MetaIndux.github.io` 的 `main` 分支发起 **Pull Request**，由维护者检查后合并。

照片路径和成员文件需要对应；使用分支或 Fork 时，将它们放在同一次修改中。不要改动其他成员资料、站点模板或发布生成文件。

提交前检查：姓名与身份准确；学生培养阶段、入学年份、年级或毕业年份已核实；链接有效；照片已上传；所有样例占位文字已删除；公开联系方式经过本人确认。

Commit 或 Pull Request 不等于网站已经发布。变更进入 `main` 后，还需等待 GitHub Actions 构建和 GitHub Pages 部署成功，再检查正式个人页面。`_members/templates/` 只存放填写说明与样例，不作为成员资料发布。
